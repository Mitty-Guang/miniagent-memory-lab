# 能体现本项目独特方法的演示（7 个）

每个演示都对应一个"不是套壳、而是做了二次开发"的点，并给出**可观察证据**与**量化数据**。
GUI 示例下拉里带 ★ 的条目就是这些演示的一键入口。

---

## 演示 1：跨会话记忆（长期记忆检索 + 注入）

**独特点**：SQLite 长期记忆 + 可插拔检索（TF-IDF 默认 / bigram / fastembed 向量），
跨会话命中后注入系统提示词；上游只有进程内的短期 `Memory`，没有跨会话能力。

**步骤**
1. 连续对话开启，输入：`记住：我的项目代号是 ORION，报告统一放在 reports 目录下，数字保留两位小数。`
2. 点「新会话」（清空短期上下文）→ 输入：`按我的偏好把 10÷3 的结果写成报告文件。`

**观察点**
- 左栏「长期记忆（本轮）」出现 **注入的历史记忆 + 相关度分数**；
- 文件落在 `reports/` 且数字是 `3.33`（两位小数）——偏好来自**上一个会话**；
- 右下记忆库出现本轮新写入的条目。

**量化**：Mem2ActBench（ACL 2026）简化协议、仅上下文不同：工具准确率 **37.5% vs 10.0%**、
参数 F1 **0.421 vs 0.145**。

## 演示 2：预算裁剪的因果（同一任务、不同预算）

**独特点**：`BudgetedMemory` 四种策略 + 字符预算；216 次扫描量化出"预算不足 → 答错"。

**步骤**
1. 先跑 `记住：我的三个幸运数字是 7、11、13。`
2. 新会话里把预算设 **300** 跑 `我最初说的三个幸运数字是多少？把它们相加写入 sum13.txt。`
3. 把预算设 **1200** 再跑一次同一句。

**观察点**
- 「本次上下文选择」卡：选中/总 消息数与字符数（低预算时关键约束被裁掉）；
- 低预算 → 答错/反问；高预算 → 正确得到 `31`。

**量化**：跨会话任务成功率 300 字符 **66.7%** → 1200 字符 **91.7%**（+25pt）。

## 演示 3：影响度记忆策略（impact，本项目的独特策略）

**独特点**：用**留一法（LOO）**估计每条历史消息对最终答案的影响度来裁剪上下文，
而不是简单的近因（recent）或相似度（relevance）；先验落在 `results/impact_priors.json`。

**步骤**
1. 记忆策略切到 `impact`，输入 `创建三个文件 f1.txt=5、f2.txt=10、f3.txt=15，计算平均值写入 avg.txt。`
2. 再切到 `recent` 跑同一句，对比「本次上下文选择」与轨迹。

**观察点**：两种策略选中的消息集合不同（impact 保留"影响决策"的消息）；
事件流中 `记忆读/记忆写` 的命中情况。

**证据**：`results/ablation_injection_*.json`、`results/impact_details.json`。

## 演示 4：联网检索的鲁棒性（相关性过滤 + 自动缩短重试）

**独特点**：Bing RSS 结构化解析（HTML 兜底）+ 中文 2-gram 相关性过滤（剔除 0 分噪声并重排）
+ 整体不相关时**自动剥离后缀词缩短关键词重搜**；`http_get` 内置 SSRF 防护。

**步骤**：输入 `查一下诺坎普球场现在能不能参观，并给出从市中心过去的交通建议（附来源）。`

**观察点**
- 工具结果首行可能出现「（原查询结果不相关，已自动改用「诺坎普球场」重搜）」；
- 回答**附来源链接**，并如实标注无法核实的部分（如官网 403）；
- 剩余 2 步时模型收到"停止检索、立即作答"的收口提醒（事件流可见）。

**量化**：修复前同一任务 20 步只回"抱歉"；修复后 19 步产出可执行方案（含双场景与交通细节）。

## 演示 5：记忆可干预（可视化 + 消融）

**独特点**：记忆库可搜索/逐条删除/清空——可现场做"记忆消融实验"；
且**失败样本不写入记忆**（避免错误信息污染长期记忆）。

**步骤**
1. 跑 `用 http_get 查北京天气并告诉我。`
2. 右下记忆库搜索"天气"，删除该条。
3. 重跑同一任务，对比「长期记忆（本轮）」是否还有注入。

**观察点**：删除后注入列表为空；失败运行（如审批全拒）后记忆条数不变。

## 演示 6：HITL 审批与工具降级

**独特点**：按工具粒度的人工审批（自动放行 / 仅 bash / 全部），拒绝后模型**自动改道**用其他工具完成同一任务。

**步骤**
1. 工具审批切「全部需审批」；
2. 输入 `用 bash 删除 note.txt（不存在就先创建再删）；如果命令被拒绝，请改用其他工具完成。`
3. 弹窗点「拒绝」。

**观察点**：事件流出现 `审批 · bash_execute 拒绝`；模型改用 `file_editor`/`python_execute` 完成；
trace 摘要中 `rejected` 计数增加。

---

## 演示 7：模型自动选运行参数（预算 / 步数）

**独特点**：1 次轻量 LLM 调用按任务复杂度给出预算与步数 + 理由，**关键词规则兜底**
+ **安全夹逼**（预算 ≥300、步数 ≥8）——把"拍脑袋默认值"变成有依据的默认值。

**步骤**：勾选「让模型自动选择预算/步数」，分别跑
`用 Python 计算 1 到 100 的和，直接告诉我结果。` 与 `搜索「Python 3.12 新特性」，给我三条摘要。`

**观察点**：「运行参数」卡显示 **类别 / 预算 / 步数 / 理由 / 来源（模型估计 or 规则兜底）**；
单轮任务 → 300 字符 / 8 步；联网研究 → 1000 字符 / 20 步；事件流有 `参数估计` 事件。

## 演示编排建议（面试 5 分钟版）

1. **演示 1**（跨会话记忆）→ 说明"记忆不是聊天记录，而是可检索、可注入的长期资产"；
2. **演示 2**（预算因果）→ 展示 216 次扫描的量化结论（答错 vs 答不完的区分）；
3. **演示 4**（联网鲁棒性）→ 讲"检索质量 + 收口时机"的定位与三层修复；
4. 收尾用 **演示 7**（模型自动选参数）+ 记忆库浏览器，说明"参数有依据、记忆可干预"。
